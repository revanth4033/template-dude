# Telugu Meme Template Library — MVP

A Netflix-style discovery platform for Telugu movie meme templates. Search by dialogue,
movie, actor or emotion; find the scene; download it.

Built to `PRD.rtf`; the build plan is in `IMPLEMENTATION_PLAN.md`.

## Running it

```bash
npm install
npm run dev          # http://localhost:3000
```

| Script | What it does |
|---|---|
| `npm run dev` | Dev server |
| `npm run build` | Production build (prerenders ~630 pages) |
| `npm run seed` | Regenerates `src/data/templates.ts` from the dialogue pool |
| `npm run placeholders` | Regenerates every placeholder PNG |
| `npm run check-search` | Sanity-checks search ranking against the PRD's example queries |
| `npm run lint` | ESLint |

## How the data works

The four metadata fields — **dialogue, movie, actor, emotion** — are the whole model
(PRD §4–§5). There is deliberately no description or situation field: the dialogue *is*
the scene, and those four fields are also the entire search index.

```
src/data/
├── movies.ts      33 movies, hand-written
├── actors.ts      16 actors, hand-written
├── emotions.ts    15 emotions with emoji + accent colour
├── dialogues.ts   ← the curated pool. This is the file you edit.
└── templates.ts   ← GENERATED by `npm run seed`. Don't hand-edit.
```

**To add templates**, add lines to `src/data/dialogues.ts` and run `npm run seed`, then
`npm run placeholders`. The seed script is deterministic (fixed RNG), so ids stay stable
and diffs stay readable.

**`src/lib/queries.ts` is the only data-access boundary.** Pages never import
`src/data/*` directly. That indirection is what makes swapping in a real database a
rewrite of one file instead of the whole app.

## Known limitations of this MVP

These are deliberate, and each is surfaced in the UI rather than hidden:

1. **All images are generated placeholders.** No real film stills exist in this repo.
   They're real PNGs at real paths (`public/templates/tpl-NNN.png`), so dropping in
   actual screenshots is a file swap — no component changes. Note that a placeholder
   renders its own dialogue as artwork, so the hero briefly looks like it repeats
   itself; that goes away with real images.

2. **Dialogue text is prototype-grade.** Transliterated from memory, with approximate
   wording and actor attribution. Verify against the films before any public launch.

3. **Upload can't really publish.** The MVP has no backend (PRD §39), so
   `/admin/upload` saves to `localStorage` — visible only in that browser, and not in
   search or browse. It produces a paste-ready record for `src/data/dialogues.ts`,
   which is the honest path to adding a template for real.

4. **Emotion distribution is uneven** — Serious has ~68 templates, Crying ~6. The seed
   script biases padding toward thin emotions so every browse page has content, but it
   can only add, not re-tag the curated base.

5. **Copyright.** Film stills and dialogues belong to their studios. Fine for a local
   prototype; worth a decision before deploying publicly.

## Deploying

Set `NEXT_PUBLIC_SITE_URL` so OG image URLs resolve, then deploy to Vercel. Everything
except `/search` prerenders as static HTML.
